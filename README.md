# آموزش Rust

سکوی فارسی آموزش Rust با درس، تمرین، آزمون و پیشرفت شخصی. ساختار دوره امکان افزودن محتوای Go در آینده را حفظ می‌کند.

## محدودیت اجرای کد و وابستگی‌های بیرونی

برنامه کد کاربران یا مثال‌ها را اجرا یا کامایل نمی‌کند. ویرایشگر صفحه کد را ذخیره نمی‌کند و اجرای خودکار یا ارسال مستقیم به Playground ندارد. کاربر می‌تواند با انتخاب خود کد را کپی کرده، در [Rust Playground](https://play.rust-lang.org/) جای‌گذاری و آنجا اجرا کند؛ در این صورت کد در اختیار سرویس بیرونی قرار می‌گیرد و دسترسی به اینترنت و پایداری آن سرویس لازم است. اطلاعات حساس را به Playground نفرستید.

### بررسی اتصال Playground

بررسی منابع در ۲۰۲۶-۱۰-۳۰: اجرای داخل سایت پیاده‌سازی نشده است؛ اجازهٔ استفادهٔ خودکار از سرویس میزبانی‌شده و قرارداد عمومی پایدار برای اتصال شخص ثالث تأیید نشدند. پیدا نشدن این تأیید به معنی ممنوع بودن سرویس نیست. برای تصمیم‌گیری، شرایط استفاده، محدودیت نرخ و مجوز اتصال را از گرداننده بگیرید و قرارداد و پایداری اتصال را تأیید کنید.

- [README مخزن Playground در نسخهٔ بررسی‌شده](https://github.com/rust-lang/rust-playground/blob/6e39b1942410a962c41ec2e1cfdc09792a5a7b45/README.md#architecture) معماری frontend و backend و محدودیت زمان و حافظه را شرح می‌دهد؛ مجوز MIT/Apache کد منبع به‌تنهایی مجوز استفادهٔ خودکار از سرویس میزبانی‌شده نیست.
- آزمون زنده با کد بی‌ضرر نوشته‌شده برای همین بررسی: درخواست `POST` به `https://play.rust-lang.org/execute` پاسخ HTTP 200، مقدار `success: true` و خروجی `hello from a test` داد. پاسخ برای مبدأ `https://example.com` سربرگ `access-control-allow-origin: *` داشت؛ پیش‌درخواست CORS در مرورگر آزمایش نشد.
- آزمون زندهٔ `wss://play.rust-lang.org/websocket` با برنامه‌ای مستقل و بی‌ضرر دو ورودی تعاملی `alpha` و `beta` را پس از نمایش درخواست‌های جداگانه دریافت و بازتاب داد و با وضعیت موفق پایان یافت. این آزمون از کلاینت Node انجام شد، نه مرورگر با مبدأ استقرار. [آزمون بالادستی ورودی جریانی](https://github.com/rust-lang/rust-playground/blob/6e39b1942410a962c41ec2e1cfdc09792a5a7b45/tests/spec/features/streaming_spec.rb) نیز سناریوی ورودی را نشان می‌دهد.
- [کلاینت رسمی WebSocket](https://github.com/rust-lang/rust-playground/blob/6e39b1942410a962c41ec2e1cfdc09792a5a7b45/ui/frontend/reducers/websocket.ts) عبارت `iAcceptThisIsAnUnsupportedApi: true` را ارسال می‌کند؛ سرور زنده نیز آن را بازگرداند. API صراحتاً پشتیبانی‌نشده است و آزمون موفق قرارداد پایدار ایجاد نمی‌کند. در منابع بررسی‌شده شرایط استفاده، مجوز اتصال خودکار شخص ثالث و محدودیت نرخ سرویس میزبانی‌شده یافت نشد؛ نبود تأیید به معنی ممنوعیت نیست.
- [تنظیمات بالادستی](https://github.com/rust-lang/rust-playground/blob/6e39b1942410a962c41ec2e1cfdc09792a5a7b45/ui/README.md#configuration) می‌گویند `PLAYGROUND_CORS_ENABLED` پشتیبانی CORS را فعال می‌کند. پیش از اتصال، مجوز و محدودیت‌ها را از گرداننده بگیرید و CORS و WebSocket را در مرورگر با مبدأ استقرار آزمایش کنید.

برنامه به MySQL و بسته‌های `requirements.txt` وابسته است. ورود با Google به سرویس و اعتبارنامه Google OAuth نیاز دارد. تأیید ایمیل در محیط عملیاتی به سرویس SMTP قابل دسترس وابسته است. فونت استعداد در پروژه موجود است و به سرویس فونت بیرونی نیاز ندارد.

## راه‌اندازی توسعه

1. محیط مجازی Python بسازید و `pip install -r requirements.txt` را اجرا کنید. نصب `mysqlclient` ممکن است به کتابخانه‌های توسعه کلاینت MySQL نیاز داشته باشد.
2. پایگاه داده MySQL با `utf8mb4` و کاربری دارای دسترسی به آن بسازید. از `.env.example` فایل `.env` بسازید، مقادیر را تکمیل و متغیرها را در محیط پوسته صادر کنید؛ Django این فایل را خودکار نمی‌خواند. `DJANGO_DEBUG=1` فقط برای توسعه است.
3. برای ورود با Google، مقادیر `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` را تنظیم و نشانی `http://localhost:8000/accounts/google/login/callback/` را در Google ثبت کنید. بدون پیکربندی Google، درخواست ورود با Google ناموفق است.
4. دستورهای `python manage.py migrate`، `python manage.py import_rust_content` و `python manage.py runserver` را اجرا کنید. واردسازی دوباره تغییرات موجود را حفظ می‌کند؛ خروجی دستور را بررسی کنید.

تأیید ایمیل الزامی است. تنظیم نمونه از backend کنسول استفاده می‌کند و پیوند تأیید در خروجی سرور توسعه نمایش داده می‌شود.

## استقرار

`DJANGO_SECRET_KEY` قوی و پایدار، `DJANGO_ALLOWED_HOSTS`، اعتبارنامه MySQL و Google و backend واقعی SMTP با فرستنده و تنظیمات TLS مناسب را تنظیم کنید. در صورت نیاز، مبدأهای HTTPS را با ویرگول در `DJANGO_CSRF_TRUSTED_ORIGINS` قرار دهید. نشانی `https://DOMAIN/accounts/google/login/callback/` را در Google ثبت کنید. پس از migration، دستور `python manage.py collectstatic` را اجرا و `staticfiles/` را از طریق وب‌سرور ارائه کنید.

با خاموش بودن debug، تغییر مسیر HTTPS، کوکی‌های امن نشست و CSRF و HSTS یک‌ساله برای دامنهٔ فعلی فعال‌اند. پیش از انتشار مطمئن شوید HTTPS برای کل دامنه پایدار است؛ HSTS بازگشت به HTTP را برای مرورگرها تا پایان مدت آن ناممکن می‌کند. اگر TLS در پراکسی خاتمه می‌یابد، فقط زمانی `DJANGO_TRUST_PROXY_HTTPS=1` را تنظیم کنید که دسترسی مستقیم به برنامه مسدود و پراکسی تمام headerهای `X-Forwarded-Proto` ورودی را حذف و خودش مقدار معتبر را جایگزین کند. در غیر این صورت header قابل جعل است. برای TLS مستقیم این متغیر را فعال نکنید.

**پیش‌نیاز امنیتی استقرار:** پیش از انتشار، در پراکسی مرزی برای همهٔ درخواست‌های `/accounts/` و `/admin/` محدودیت نرخ بر اساس IP واقعی، سقف هم‌زمانی و پاسخ 429 تنظیم کنید؛ به‌ویژه ورود، ثبت‌نام، بازنشانی رمز، تأیید ایمیل و ورود Google. دسترسی admin را علاوه بر آن با شبکه یا VPN محدود کنید. مقادیر را با ترافیک واقعی تنظیم و با درخواست‌های آزمایشی بررسی کنید. IP را فقط از پراکسی‌های مورد اعتماد استخراج کنید و headerهای دریافتی از کاربران را نپذیرید. محدودیت‌های داخلی allauth جایگزین این حفاظت نیستند: cache پیش‌فرض محلی و جدا برای هر پردازه است و پشت پراکسی ممکن است IP پراکسی را ببیند. بدون این حفاظت، افزایش پردازه یا نمونه محدودیت را دور می‌زند و admin محدودکنندهٔ داخلی ندارد. برای محدودسازی سراسری داخلی، cache مشترک با عملیات اتمی و تنظیم امن IP واقعی لازم است.

نمونهٔ Nginx برای یک پراکسی مرزی مستقیم؛ دستور `limit_req_zone` در بلوک `http` و `location` در بلوک سرور HTTPS قرار می‌گیرد. همهٔ درخواست‌ها، از جمله درخواست‌های نامعتبر، شمارش می‌شوند. برنامه باید فقط روی loopback گوش دهد. اگر CDN یا پراکسی دیگری جلوتر است، ابتدا ماژول real IP را فقط برای شبکه‌های مورد اعتماد آن تنظیم کنید؛ در غیر این صورت همهٔ کاربران ممکن است یک IP مشترک داشته باشند.

```nginx
# http
limit_req_zone $binary_remote_addr zone=sensitive:10m rate=5r/m;

# server: HTTPS
location ~ ^/(accounts|admin)(/|$) {
    limit_req zone=sensitive burst=10 nodelay;
    limit_req_status 429;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_pass http://127.0.0.1:8000;
}
```

این نمونه به‌تنهایی پیکربندی کامل TLS، سایر مسیرها، سقف هم‌زمانی یا محدودسازی شبکهٔ admin نیست. قبل از اعمال، پیکربندی نهایی را با `nginx -t` و آزمون عملی بررسی کنید. اگر چند پراکسی مرزی دارید، شمارنده‌ها بین آن‌ها مشترک نیستند؛ محدودسازی سراسری را در لایهٔ مشترک اجرا کنید.

احراز هویت Google با ایمیل و اتصال خودکار حساب غیرفعال‌اند. کاربران موجود به رکورد ایمیل تأییدشده allauth نیاز دارند؛ بدون بررسی مالکیت ایمیل، آن را تأییدشده علامت نزنید.

## پشتیبان‌گیری و آزمون بازیابی MySQL

پشتیبان شامل داده‌های کاربران و نتایج است؛ آن را رمزگذاری کنید، دسترسی را محدود نگه دارید و خارج از مخزن و سرور برنامه نگهداری کنید. نام پایگاه داده و کاربر زیر نمونه‌اند. ابزارهای `mysqldump` و `mysql` و دسترسی مناسب لازم‌اند؛ گزینه `-p` رمز را تعاملی می‌پرسد. برای جدول‌های تراکنشی InnoDB، نمونه زیر snapshot سازگار می‌گیرد؛ هنگام پشتیبان‌گیری تغییر ساختار جدول انجام ندهید:

```sh
mysqldump -h 127.0.0.1 -u backup_user -p --single-transaction --routines --triggers --events learn_rust > learn_rust_backup.sql
```

بازیابی آزمایشی را فقط در پایگاه داده‌ای جدا و خالی، ترجیحاً روی سرور ایزوله، انجام دهید. هرگز فایل پشتیبان را برای آزمون روی پایگاه داده عملیاتی وارد نکنید؛ بازیابی ممکن است داده‌های مقصد را بازنویسی یا حذف کند. پس از ساخت پایگاه داده خالی `learn_rust_restore_test` با `utf8mb4` و دادن مجوز به کاربر بازیابی، اجرا کنید:

```sh
mysql -h 127.0.0.1 -u restore_user -p learn_rust_restore_test < learn_rust_backup.sql
```

سپس با تنظیم متغیرهای `MYSQL_DB`، `MYSQL_USER`، `MYSQL_PASSWORD`، `MYSQL_HOST` و `MYSQL_PORT` برای محیط ایزوله، اتصال، داده‌های دوره، حساب‌ها و تاریخچه آزمون را بررسی و `python manage.py showmigrations` را اجرا کنید. بازیابی آزمایشی را دوره‌ای تکرار و فایل و پایگاه داده آزمایشی را طبق سیاست نگهداری امن حذف کنید.

## بررسی و محدودیت آزمون

دستورهای `python manage.py check`، `python manage.py makemigrations --check --dry-run` و `python manage.py test accounts learning progress` را اجرا کنید. کاربر MySQL آزمون به مجوز ساخت پایگاه داده آزمون نیاز دارد. ۳۳ آزمون روی MySQL 26.10.0 در نمونه‌ای موقت و ایزوله موفق شدند. MySQL همچنان هشدار `models.W036` برای محدودیت‌های شرطی allauth می‌دهد؛ migration `accounts.0002` به‌جای آنها ایندکس‌های یکتای معادل می‌سازد و درج و به‌روزرسانی تکراری در آزمون MySQL بررسی شده‌اند. پیش از استقرار، پشتیبان بگیرید و داده‌های تکراری را بررسی کنید؛ جزئیات در `accounts/INTEGRATION.md` آمده است. اتصال به نمونهٔ پیش‌فرض محلی بدون اعتبارنامه با خطای `Access denied for user 'root'@'localhost' (using password: NO)` مواجه شد.
